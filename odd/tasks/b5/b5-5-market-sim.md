## Specs

- S1 `@trading/market-sim` is a pure package that depends only on `@trading/domain`: no I/O, no `Date.now()`, no `Math.random()`; time comes from an injected `Clock` and randomness from a seeded generator.
- S2 The same seed, clock and inputs produce the same sequence of prices (determinism), and a different seed a different one.
- S3 Modes `PAUSED`, `NORMAL`, `VOLATILE`, `BULLISH` and `BEARISH` and the scenarios `STABLE_MARKET`, `BULLISH_SESSION`, `VOLATILE_SESSION`, `SHARP_DRAWDOWN` and `RECOVERY` move the price as `12-demo-mode-spec.md` §37 to §40 describe; a price never goes to zero or below.
- S4 A tick returns the new price and `tickChange`, the tick-to-tick delta (ADR-007 point 14), while `change` and `changePercent` stay against the last closed daily candle.
- S5 At a UTC day rollover the engine returns the closed daily candle for each asset; given a gap of offline days it deterministically generates the missing candles so the daily series has no holes.

## Log

- 2026-10-23: the user approved every decision at the recommendation and asked for the whole slice in one run, one commit per task.
- Decisions: the package declares its own `Clock` (same shape as the application port) because it may import only `@trading/domain`; the lint boundary also bans `Math.random()`, `Date.now()` and `new Date()` in its source. Each asset draws from its own generator (`seed:assetId`), so an asset's series does not change when another asset is added.
- Price model: a geometric random walk (`exp(drift + volatility * N(0,1))`) rounded to cents with a floor of `0.01`, so a price never reaches zero. Mode and scenario numbers are demo-tuned constants for a 1 second tick, in `mode.ts` and `scenario.ts`.
- Open detail of 08-realtime-spec.md section 40, decided here: in `PAUSED` mode `tick()` returns no ticks, uses no sequence and does not advance a running scenario. A scenario replaces the mode while it runs and hands back to the mode when it ends.
- Candles: `tick()` closes every UTC day before the clock's day (also while `PAUSED`); `takeClosedCandles()` returns them once. A day with ticks closes from them (volume = ticks x 10); a day without ticks (offline start, fast clock) is generated by a 48 step walk seeded by `seed:assetId:day`. `AssetSeed.lastCandleAt` drives the backfill at start; without it nothing is backfilled.
